Chapter 1

EtherCAT 到底是什么

EtherCAT 是建立在标准 IEEE 802.3 以太网物理层上的工业实时总线。它使用普通的 100BASE-TX 收发电气规范，但处理帧的方式与普通 TCP/IP 网络不同。

应用语义CiA402 / 自定义对象“使能电机”“目标速度 1000 rpm”“读取实际位置”
应用协议CoE / PDO / SDO怎样组织周期数据、怎样访问对象字典
EtherCAT 核心Datagram / FMMU / SM逻辑寻址、现场内存映射、缓冲区同步
以太网帧EtherType 0x88A4EtherCAT Datagram 被装进 Ethernet Payload
物理层100BASE-TX网线、磁性器件、PHY、电信号

它为什么快

传统现场总线常常是主站逐个询问：问 1 号、等回答；问 2 号、再等回答。EtherCAT 主站可以发出一帧，其中包含多个从站的数据。帧沿链路经过所有从站，每个 ESC 都在帧流经时处理自己的几个字节，这叫 processing on the fly。

注意：“on the fly”不代表数据神奇地不经过缓存，而是 ESC 有专用硬件流水线，在极小延迟下完成匹配、读写和 WKC 更新，无需 MCU 收完整帧再软件解析。

它不是什么

不是 TCP/IP
  • 没有 TCP 连接
  • 不依赖 IP 地址
  • 不走 Socket 应用协议
  • EtherType 是 0x88A4
也不是 CAN 总线
  • 虽然 CoE 借用了 CANopen 的对象模型
  • 线上的帧仍然是 EtherCAT Ethernet
  • CoE 是 CANopen over EtherCAT，不是物理 CAN

它不是 CRC，而是“有多少预期操作被从站成功执行”的证明。

WKC 怎么理解

假设一个 LRW Datagram 预期同时让 3 个从站读/写其映射区，主站会预先算出期望 WKC。实际返回值少了，说明至少有一个对应操作没有成功。WKC 能告诉你“过程数据链不完整”，但单靠它不能直接指出是哪一个物理原因。

Chapter 3

三类寻址：从发现设备到周期通信

APRD / APWR / APRW

上电时主站还不知道拓扑中每个设备的固定地址，所以利用从站在帧经过时修改位置计数的机制，按物理顺序访问第 1、2、3 个从站。主要用于扫描和初始化。

FPRD / FPWR / FPRW

主站给每个从站设置一个 Station Address，之后就能按“从站地址 + ESC 寄存器偏移”访问指定设备。适合配置单个从站寄存器。

LRD / LWR / LRW

主站构造一整片 32 位逻辑地址空间。每个从站的 FMMU 只匹配属于自己的位或字节。周期 PDO 通常使用逻辑寻址，一条 LRW 就能覆盖多个从站。

FMMU 映射实验

拖动“从站逻辑起始地址”和“PDO 长度”，观察一片主站逻辑内存如何映射到某个从站。

FMMU 判断 Datagram 的逻辑地址范围是否与自身配置重叠，并把命中的字节映射到本地 Process RAM。

每周期：主站发帧 → LAN9252 更新 RxPDO → STM32 取命令并更新反馈 → LAN9252 把 TxPDO 写回帧 → 主站接收。

一次 SDO 读取

1. 主站发 CoE SDO Upload Request

例如读取 0x1018:01 Vendor ID。

2. 请求进入 SM0 Mailbox

LAN9252 触发 AL Event，SSC 从邮箱取出请求。

3. SSC 查询对象字典

检查对象是否存在、访问权限、长度和当前状态。

4. 响应写入 SM1 Mailbox

主站在后续帧中读取响应；失败则返回 SDO Abort Code。

为什么 PDO 快：PDO 不在每个周期携带 0x6040 这样的对象索引。双方早已约定“第 0～1 字节就是 Controlword”，因此只传纯数据。
Chapter 7

CoE 与对象字典

CoE（CANopen over EtherCAT）复用了 CANopen 的对象字典和设备配置思想。它不是在网线上发送 CAN 帧，而是把 CANopen 风格的服务装入 EtherCAT Mailbox。

对象地址 = Index + SubIndex

范围/对象用途例子
0x1000–0x1FFF通信与身份对象0x1018 Identity Object
0x1600RxPDO Mapping每个子项描述一个映射对象及 bit 长度
0x1A00TxPDO Mapping例如 Statusword、Actual Position
0x1C12 / 0x1C13SM PDO Assignment指定 SM2/SM3 使用哪些 PDO
0x6000–0x6FFF设备 ProfileCiA402 的 0x6040、0x6041

PDO 映射值怎么读

一个 32 位映射描述符通常编码为：

31                   16 15          8 7          0
+----------------------+--------------+------------+
|      Index (16)      | SubIndex (8) | Bits (8)   |
+----------------------+--------------+------------+

0x60400010 = Index 0x6040, SubIndex 0, 长度 0x10 = 16 bit
0x607A0020 = Index 0x607A, SubIndex 0, 长度 0x20 = 32 bit

所以一个典型 RxPDO 0x1600 可以依次放：

0x60400010  Controlword       16 bit
0x607A0020  Target Position   32 bit
0x60FF0020  Target Velocity   32 bit
0x60600008  Mode of Operation  8 bit
字节序：EtherCAT 字段和对象通常按 little-endian 解释。STM32G474 本身也是 little-endian，但仍应通过明确的类型和拷贝处理，避免未对齐访问、结构体填充和编译器差异。

最常见的使能序列

Shutdown：Controlword 0x0006

驱动从 Switch on disabled 进入 Ready to switch on。

Switch on：0x0007

进入 Switched on，功率级准备就绪。

Enable operation：0x000F

进入 Operation enabled，此时才允许 FOC 使用目标值。

Fault reset：设置 bit 7

只在故障原因已解除时进行复位，不能用它掩盖持续故障。

实现要点：不要只比较整个 Statusword 是否等于某个常数。规范中的状态判断使用掩码，因为制造商位、远程位、目标到达位等可能同时变化。

DC 分布式时钟：让所有从站在同一时刻行动

PDO 周期稳定不代表各从站本地控制中断严格同相。Distributed Clocks（DC）通过每个支持 DC 的 ESC 内部时钟、链路延迟测量和偏差校正，建立统一时间基准。

→

DC 需要处理四件事：

  1. 测量各段传播延迟。
  2. 选择 Reference Clock。
  3. 调整从站本地 System Time 的 Offset 和 Drift。
  4. 配置 SYNC0/SYNC1 的周期与相位。
移植顺序：先让 FreeRun 模式下 PDO 稳定进入 OP，再做 SyncManager 同步，最后做 DC。否则“进不了 OP”会同时混入 SPI、PDO 映射、ESI 和时钟四类变量，定位非常慢。
Chapter 10

LAN9252 与 STM32 的 SPI PDI

LAN9252 的 EtherCAT 网络侧由芯片硬件处理；STM32 面对的是 PDI（Process Data Interface）。你的板使用 SPI，因此 MCU 不解析网线上的完整 EtherCAT 帧，而是访问 LAN9252 的寄存器和内存窗口。

SPI3 SCKPC10，时钟
SPI3 MISOPC11，ESC → MCU
SPI3 MOSIPC12，MCU → ESC
CSPA3，片选
ESC_INTPA4，AL Event 中断
SYNC0PA5，DC 同步中断
SYNC1PA6，可选同步信号
RESETPC4，硬件复位

三类底层访问

访问用途关键机制
直接 SPI 寄存器访问 LAN9252 系统寄存器0x03 读、0x0B Fast Read、0x02 写
CSR间接访问 EtherCAT Core Register写 CSR Data/Command，轮询 Busy，取回结果
PRAM FIFO批量访问 Process RAM配置地址和长度，通过读写 FIFO 搬运 PDO/邮箱数据

一次 ESC CSR 读取的伪代码

uint32_t lan9252_csr_read(uint16_t esc_addr, uint8_t size)
{
    spi_write(CSR_CMD, make_read_cmd(esc_addr, size));

    for (uint32_t retry = 0; retry < CSR_TIMEOUT; ++retry) {
        uint32_t cmd = spi_read(CSR_CMD);
        if ((cmd & CSR_BUSY) == 0) {
            return spi_read(CSR_DATA);
        }
    }

    report_esc_timeout();
    return 0;
}
禁止无限轮询 Busy：如果 SPI 断线、LAN9252 未出复位或时序配置错误，无限 while 会把整个实时控制程序锁死。每次等待都必须有超时和错误计数。

中断分别代表什么

  • ESC_INT / AL Event：邮箱到达、SM 数据更新、状态请求等 ESC 事件。
  • SYNC0：DC 产生的确定时刻脉冲，适合驱动同步应用任务。
  • 1 ms Timer：SSC 的协议定时、状态机和超时维护，不等同于 10 kHz FOC 电流环。

PDO 与 FOC 之间不要直接共享一堆散变量

typedef struct {
    uint16_t controlword;
    int8_t   mode;
    int32_t  target_position;
    int32_t  target_velocity;
    int16_t  target_torque;
    uint32_t sequence;
} FocCommandSnapshot;

typedef struct {
    uint16_t statusword;
    int8_t   mode_display;
    int32_t  actual_position;
    int32_t  actual_velocity;
    int16_t  actual_torque;
    uint16_t error_code;
    uint32_t sequence;
} FocStatusSnapshot;

EtherCAT 上下文完成一整组字段后再发布 command snapshot；FOC ISR 只在序号一致时接收。反馈同理。这样可避免 32 位目标值更新到一半时被另一个中断读走。

迁移前的硬资源检查

  • 确认 PC10/PC11/PC12、PA3～PA6、PC4 在实际 PCB 上与 LAN9252 相连。
  • 新增 SPI3：Mode 0、8-bit、MSB first，先用低速验证，再提升到例程约 10.6 Mbit/s。
  • 新增 ESC_INT、SYNC0、SYNC1 的 EXTI，并明确中断优先级。
  • 新增 TIM2 或其他独立 1 ms 协议定时器，不复用 TIM3 10 kHz FOC 定时器。
  • 核对 LAN9252 EEPROM/SII、ESI XML、固件对象字典的 Vendor ID/Product Code/Revision。
  • 检查 SSC 源码许可，确认允许在目标产品中复用。
Chapter 12

不用 TwinCAT：KickCAT 主站怎么工作

你下载的 KickCAT 已经构建出了工具和例程。Windows 下它通过 Npcap 直接收发二层 Ethernet 帧。这里的“网卡接口名”是 Npcap 设备名，不是 IP 地址。

环境原则

  • 使用有线以太网口，最好由 EtherCAT 独占。
  • 安装与当前程序架构匹配的 Npcap；必要时以管理员权限运行。
  • 先断开 Wi-Fi、VPN 和虚拟网卡对选择过程的干扰，但不要盲目卸载驱动。
  • Windows 适合扫描、SDO/PDO 和功能验证，不适合最终严格 1 ms 硬实时。

Chapter 13

分层定位，而不是盯着“进不了 OP”

现象先查哪一层最有价值的证据

Chapter 14

从零到转动的最小验证路线

阶段 A：只验证 SPI

复位 LAN9252，读 Byte Test 和 Chip ID。此时不要运行 SSC，不接电机输出。

阶段 B：只验证 ESC

读 ESC 基础寄存器、DPRAM 大小、AL Status，确认 CSR 和 PRAM 都可靠。

阶段 C：主站扫描

KickCAT 发现设备；核对 0x1018 与 SII/ESI。

阶段 D：邮箱

INIT → PREOP；通过 SDO 读取身份、对象列表和一个自定义参数。

阶段 E：最小 PDO

先映射一个 16-bit 输出计数器和一个 16-bit 输入回显，进入 SAFEOP/OP。

阶段 F：CiA402，不上功率

验证 Controlword/Statusword 状态迁移，模拟位置和速度反馈。

阶段 G：接入 FOC

先低限幅、空载、小目标；实现通信丢失自动停机和输出看门狗。

阶段 H：同步和稳定性

最后加入 DC/SYNC0，做长时间 WKC、抖动、断线重连和故障注入测试。

可交付的第一里程碑：KickCAT 能扫描设备、读取 0x1018，进入 OP，并让一个主站计数值经 RxPDO 到 STM32 后加一，再通过 TxPDO 返回。这个闭环通了，再接电机。
Chapter 15

从 CAN 迁移到 EtherCAT：信号不变，承载方式改变

迁移的核心不是把 CAN ID 换成 EtherCAT 地址，而是重新定义“周期过程数据”和“非周期参数”。CAN 的 ID、长度和字节位置，需要变成 EtherCAT 的 PDO 映射、对象字典和状态机语义。

先把旧 CAN 协议写成信号清单

假设旧系统使用扩展帧 0x200 下发控制命令，0x280 返回状态。下面只是迁移示例，实际字段应以你的 CAN 协议文档和 FOC 量纲为准。

0x200 控制2–3目标速度int16，rpm 或内部速度单位RxPDO 0x60FF，通常 int32
0x200 控制4–5电流/转矩限制uint16，0.1 A/LSBRxPDO 0x6071 或自定义对象
0x200 控制6–7序号/保活递增计数器可作为自定义 RxPDO，或由 EtherCAT WKC/看门狗替代

迁移原则：CAN ID 是“消息类别”；EtherCAT PDO 是“预先约定的内存布局”。不要把 0x200 硬编码成某个 EtherCAT 地址。先确定信号含义，再决定它属于哪个 PDO 或 SDO。

例子一：STM32 接收 RxPDO 控制命令

下例把一个 RxPDO 解释为：控制字、模式、目标速度、目标转矩。生成式 SSC 工程的变量名可能不同，所以重点看数据流和边界检查。

typedef struct {
    uint16_t controlword;       // 0x6040
    int8_t   mode;              // 0x6060
    int32_t  target_velocity;   // 0x60FF
    int16_t  target_torque;     // 0x6071
} RxPdo;

static volatile RxPdo rx_pdo;
static FocCommandSnapshot command_snapshot;

void APPL_OutputMapping(const uint8_t *process_ram, uint16_t length)
{
    if (length < 9U) {
        return;                 // 2 + 1 + 4 + 2 = 9 bytes
    }

    RxPdo next;
    memcpy(&next.controlword,       process_ram + 0, 2);
    memcpy(&next.mode,              process_ram + 2, 1);
    memcpy(&next.target_velocity,   process_ram + 3, 4);
    memcpy(&next.target_torque,     process_ram + 7, 2);

    // 在协议上下文中一次性发布，FOC ISR 只读取已完成的快照
    command_snapshot.controlword = next.controlword;
    command_snapshot.mode = next.mode;
    command_snapshot.target_velocity = next.target_velocity;
    command_snapshot.target_torque = next.target_torque;
    command_snapshot.sequence++;
}

void foc_control_isr(void)
{
    FocCommandSnapshot cmd = command_snapshot;
    cia402_update(cmd.controlword, cmd.mode);
    foc_set_velocity(cmd.target_velocity);
    foc_set_torque_limit(cmd.target_torque);
    foc_current_loop();
}
不要直接把接收缓冲区当成 FOC 变量：PDO 可能在另一个中断或主循环阶段更新。应先复制成完整快照，再做 CiA402 检查、限幅和单位换算。

例子二：STM32 发送 TxPDO 状态反馈

typedef struct {
    uint16_t statusword;        // 0x6041
    int8_t   mode_display;      // 0x6061
    int32_t  actual_velocity;   // 0x606C
    int32_t  actual_position;   // 0x6064
    uint16_t error_code;        // 0x603F
} TxPdo;

static volatile FocStatusSnapshot status_snapshot;

void foc_publish_status(void)
{
    FocStatusSnapshot next = {
        .statusword = cia402_get_statusword(),
        .mode_display = foc_get_mode(),
        .actual_velocity = foc_get_velocity(),
        .actual_position = encoder_get_position(),
        .error_code = foc_get_error_code()
    };
    status_snapshot = next;
}

void APPL_InputMapping(uint8_t *process_ram, uint16_t capacity)
{
    if (capacity < 13U) {
        return;                 // 2 + 1 + 4 + 4 + 2 = 13，按实际映射核对
    }

    TxPdo tx = status_snapshot;
    memcpy(process_ram + 0,  &tx.statusword,       2);
    memcpy(process_ram + 2,  &tx.mode_display,     1);
    memcpy(process_ram + 3,  &tx.actual_velocity,   4);
    memcpy(process_ram + 7,  &tx.actual_position,   4);
    memcpy(process_ram + 11, &tx.error_code,       2);
}

这组字段实际占 13 字节。工程中应改成由最终 PDO 映射或生成代码提供的精确长度常量。

例子四：KickCAT 主站周期收发 PDO

// 伪代码：API 名称按你本地 KickCAT 版本调整
auto [nominal, redundancy] = createSockets("EtherCAT 网卡名", "");
auto link = std::make_shared<Link>(nominal, redundancy, callback);
Bus bus{link};

bus.init();
bus.requestState(State::PRE_OP);
bus.waitForState(State::PRE_OP, timeout);

// 先用 SDO 配置或确认 PDO，再创建主站过程映像
// 例如：RxPDO = 0x6040 + 0x6060 + 0x60FF + 0x6071
bus.createMapping(iomap, sizeof(iomap));
bus.requestState(State::SAFE_OP);
bus.waitForState(State::SAFE_OP, timeout);
bus.requestState(State::OPERATIONAL);
bus.waitForState(State::OPERATIONAL, timeout);

for (;;) {
    iomap.controlword = 0x000F;       // Enable operation
    iomap.mode = 9;                   // 示例：CSV，按设备支持的模式填写
    iomap.target_velocity = 1000;     // 目标速度，按 ESI/对象量纲
    iomap.target_torque = 0;

    bus.sendLogicalRead(iomap_address, iomap_size);
    bus.sendLogicalWrite(iomap_address, iomap_size);
    bus.finalizeDatagrams();
    bus.processAwaitingFrames();

    printf("status=0x%04x vel=%ld wkc=%u\\n",
           iomap.statusword, iomap.actual_velocity, bus.getWorkingCounter());
    timer.wait_next_tick();
}
主站发指令的本质：写入主站过程映像中的 RxPDO 字段，然后发送逻辑写 Datagram。主站不需要知道 LAN9252 的 SPI 寄存器；那是从站内部端口层的工作。

例子五：参数用 SDO，不要硬塞进 PDO

// 伪代码：启动阶段读取与写入参数
uint32_t vendor = sdo_upload<uint32_t>(slave, 0x1018, 1);
int32_t max_velocity = sdo_upload<int32_t>(slave, 0x607F, 0);
sdo_download<int32_t>(slave, 0x6080, 0, 3000); // 最大速度示例

// 周期控制只放实时信号：
// RxPDO: Controlword / Mode / Target velocity
// TxPDO: Statusword / Actual velocity / Error code

经验规则：控制环每周期都用到的值进 PDO；只在启动、换配方或诊断时访问的值进 SDO。把最大速度、加速度、编码器方向等参数放进 PDO，会增加周期带宽，也会让安全边界变得不清晰。

推荐迁移顺序

  1. 冻结旧 CAN 协议：列出每个 ID、字段、字节序、缩放、超时和故障语义。
  2. 定义 EtherCAT ESI 和对象字典：优先采用 CiA402 标准对象，确有需要再加厂商自定义对象。
  3. 先做一个最小 RxPDO/TxPDO 回环，不接功率级。
  4. 实现 CiA402 状态机映射，确保通信 OP 和驱动 Operation enabled 分开判断。
  5. 接入 FOC：目标值做单位换算、限幅、斜坡；反馈值带有效性和故障码。
  6. 用 WKC、SM watchdog、CiA402 Fault 三层机制替代 CAN 的单一超时判断。
  7. 最后做 DC、断线重连、异常注入和长时间运行。
兼容旧上位机的过渡方案：可以保留一个 CAN-EtherCAT 网关，让旧 CAN 主站继续发原来的 0x200/0x280，网关把信号转换为 EtherCAT PDO。这样能先验证下位机 EtherCAT，再独立迁移上位机，但网关不应成为最终闭环的长期实时瓶颈。
