# 开环高速运转 + 滑模观测器(SMO)数据采集 —— 使用说明

> **不需要编码器。** 驱动角由固件自己积分(真正的开环), 观测器只负责告诉你
> "电机到底转没转、转多快"。
>
> 适用工程: `F405_M3508_FOC`(STM32F405 + M3508)
> 相关文件: [FOC/src/VF.c](FOC/src/VF.c) · [FOC/src/SMO.c](FOC/src/SMO.c) ·
> [BSP/src/App_FOC.c](BSP/src/App_FOC.c) · [tools/smo_capture.py](tools/smo_capture.py) ·
> [tools/verify_smo.py](tools/verify_smo.py)

---

## 0. 先看这一节:动手之前必须知道的 5 件事

1. **开环 = 没有位置反馈, 也没有电流/转矩保护。** 电压加多少就加多少, 电流由负载决定。
   电机必须**固定牢、轴上空载**,人不要碰联轴器;听到异响/闻到味道立刻断电。
2. **没有编码器时, 唯一能发现"电机没转"的证据是反电动势。** 固件已实现该保护:
   对齐 300ms 之后、指令电频率超过 `fe_min` 后开始计时, **2000ms** 内 `|E|` 不到 0.35V
   → 判定失步/堵转 → **封驱动 + 关 EN + 退开环**。
3. **被保护封过之后, 直接再发 `vf` 就能重来**(使能时会把失步锁清掉)。
   想临时关掉保护做台架试验: `prot 0`(注意: 关了就真没有堵转保护了);`prot 1` 打开。
4. **12V 母线时相电压上限 ≈6.9V**(SVPWM 线性区 = vdc/√3), 默认 `vmax=6.5V`。
   反电动势低于 `OBS_EMF_MIN_V`(0.3V)时观测器自己都认为角度不可信, 所以
   **电机侧约 478rpm 以下没有可靠观测角**, 开环低速段只能靠 V/F 硬拖。
5. **观测角只用于诊断,不参与驱动**(驱动角是积分角)。所以观测器算错也不会飞车,
   但反过来,**开环能不能转起来全靠 V/F 参数**,见 §3.4。

## 1. 驱动角从哪来(这是这次改的核心)

```
        ┌─────────────────────────────────────────────┐
        │  θ_drv = 2π·∫fe·dt   ← 固件自己积分(开环)     │──► SVPWM ──► 电机
        └─────────────────────────────────────────────┘
                 ▲
        fe = 指令rpm/60 × 极对数   (从 f_start=0.5Hz 起斜坡上升)

        实测 iαβ ──┐
                   ├──► 滑模观测器 ──► |E| / ω̂ / θ̂ ──► ① 失步保护 ② 打点
        指令 vαβ ──┘
```

- **起步**: 使能后先在固定角上按 `valign`(默认 1.5V)停 300ms, 把转子拉到已知位置,
  然后从 `f_start`(0.5Hz ≈ 4.3rpm 电机侧)开始积分、按斜坡升频升压。
- **两种驱动角模式**(`drv` 命令 / CAN 0x28):
  - `drv 0` = 开环积分角 ← **默认, 没有编码器就用这个**
  - `drv 1` = 编码器电角度 + 转矩角(台架上有编码器时更稳)
- **反馈**: 开环模式下 `rpm_meas` 直接用观测器的 ω̂(不再依赖编码器差分);
  `|E|` 一旦建立就认为牵入成功,`vf_running=1`。

## 3. 上位机操作(全程走 USB,不需要 CAN 盒)

### 3.1 确认命令通

复位后串口应打出:

```
# boot: SMO k=50.0 delta=8.0 alpha=0.140 lagw=400 | VF default drv=openloop rpm=1500 ...
```

敲 `stat`,重点看三行:

```
# mode=FOC-CLOSED rpm_cmd=0 ... |E|=0.00 ...        ← 还没进开环
# tim1 CR1=0x0081 CCER=0x1111 ARR=2100 CCR4=2050 drv=0 vdc_fault=0 usb_drop=0
# smo_dir ok=0 bad=0 -> 无编码器, 不判定(开环模式属正常)
```

进开环之后,**不开打点流也会每 500ms 打一行实时诊断**(这是排查"不转"的第一手材料):

```
# OL t=12345 v_out=2.80V I=14.2A |E|=0.05V rpm_cmd=180 rpm_obs=0 vdc=12.1
     aligned no-emf boost_lo | vlo=2.80 fres=6.0 fstart=2.0 prot=1
```

逐字段读:`v_out` 有没有给出去 → `I` 有没有上来 → `|E|` 有没有建立 →
结尾三个状态词(`aligned/aligning`、`running/no-emf`、`boost_lo/curve`)。

### 3.2 第一次试转(务必从小转速/短时间开始)

```
vf 300          # 进开环(先对齐 300ms, 再从 0.5Hz 升频), 目标 300rpm(电机侧)
stream 1        # 开始 1kHz 打点
stat            # 看 |E| 有没有起来、有没有报 STALL
vf 1200
vf 2000
stop            # 退出, 三相封零
```

`vf` 之后 1~2 秒内应该看到 `|E|` 从 0 涨到 0.4V 以上、`rpm_obs` 跟上指令。
若 800ms 内 `|E|` 没起来, 固件会打印并封驱动:

```
# STALL: |E|=0.05V rpm_cmd=300 -> 封驱动(检查 vboost/slope/align)
```

看到这行:**先退 `stop`,再按 §3.4 调参数**,不要反复硬冲。

### 3.3 采集(脚本自动扫速)

```powershell
# 依次 600 -> 1200 -> 2000 -> 3000 rpm, 每档 5s, 结束自动分析
python tools/smo_capture.py --port COM7 --sweep 600,1200,2000,3000 --dwell 5 --out data/sweep1.csv
```

脚本会自己发 `stream 1` / `vf 600` / … ,结束发 `stop`;分析模式由文件头里的
`drv=openloop` 自动判定(无编码器走开环判据)。

> 采集只用标准库(内置 ctypes 串口读循环),不需要 pyserial。
> `--plot` 需要 matplotlib,`--list-ports` 需要 pyserial,本机都没装,不加不影响。

### 3.4 参数拐点(开环成败基本都在这几个)

| 命令 | 作用 | 默认 | 现象 → 怎么调 |
|------|------|------|--------------|
| `vlo <V>` | **低频强制启动电压** | 2.8 | **堵转/一冲就停 → 加到 3.5~4.5**;电流太大发热 → 回调 |
| `fres <Hz>` | 低频强制段上界 | 6 | 起步无力/牵不进 → 提到 8~10 |
| `vboost <V>` | 牵入后的低速补偿 | 1.0 | 转起来后低速段抖 → 加一点 |
| `slope <V/Hz>` | V/F 斜率 | 0.05 | 转速上不去、vdc 打满 → 调小;带载掉速 → 调大 |
| `vmax <V>` | 电压上限 | 6.5 | 12V 母线别超 6.9;24V 可到 13 |
| `fstart <Hz>` | 起始电频率 | 2.0 | 起步就堵 → 3~5;起步顿挫 → 保持小值 |
| `valign <V>` | 对齐电压 | 1.5 | 对齐时"咔"一声正常;不想对齐设 0 |
| `ramp <rpm/s>` | 转速斜坡 | 600 | 起步电流大 → 降到 200~300 |
| `prot <0\|1>` | 失步保护开关 | 1 | 想排除"是不是保护在捣乱" → `prot 0` 试一次(会失去堵转保护) |

#### 为什么需要"低频强制启动电压"

V/F 曲线在 `fe→0` 时 `V→vboost`(只有 1V),电流 ≈ 1V/0.194Ω ≈ 5A,
折算输出轴转矩 ≈1N·m —— **顶不住 M3508 那套 19:1 行星减速箱的静摩擦**,
现象就是原地堵转、或者"嗡"一声就停。

所以固件在**牵入成功前**或**电频率低于 `fres`**时,把电压强行抬到 `vlo`(默认 2.8V),
电流上到 12~18A,先把它拖起来;`|E|` 一建立就立刻退回正常 V/F 曲线(否则会过热)。

> ★这是**起步专用**的粗活:电流大、发热快。`vlo` 别长期挂太高,牵入后确认它已经退回曲线
> (打点里 `vcmd` 列会从 2.8 掉到 `1.0+slope·fe`,`flags` 的 bit1 会清零)。

## 4. 怎么看结果(开环判据)

CSV 列:
`t_ms, theta_obs, theta_enc, err, emf, omega_obs, rpm_obs, rpm_enc, ialpha, ibeta, valpha, vbeta, vdc, imag, vcmd, flags`

**没有编码器时, `theta_enc / err / rpm_enc` 三列是垃圾,别理它们。** 重点看:

| 列 | 含义 | 判据 |
|----|------|------|
| `emf` | 观测到的反电动势 V | 这是"电机真的在转"的**唯一证据**:600rpm≈0.44V、1200≈0.88V、2000≈1.47V、3000≈2.20V |
| `rpm_obs` | 观测器给的电机侧转速 | 末段应接近 `rpm_cmd`(开环有 5~20% 转差属正常) |
| `imag` | **电流矢量幅值 A** | 堵转时它顶到限流;正常运转 3~8A |
| `vcmd` | 本拍输出电压幅值 V | 起步段应是 `vlo`(2.8V),牵入后应掉回 `1.0+0.05·fe` |
| `vdc` | 母线电压 | 别掉到 11V 以下 |
| `flags` | bit0 已牵入 / bit1 低频强制段 / bit2 失步 / bit3 对齐完成 | bit1 长期为 1 = 一直没牵入 |

#### 堵转怎么定位(脚本会自动给结论)

```
电压: 输出峰值 2.80V, 母线最低 12.00V  电流: 峰值 13.8A, 平均 13.8A
★ 全程没有反电动势 —— 电机没转。按下面顺序定位:
  ② 电压 2.80V 下电流已经 13.8A 还不转: 纯粹是起动转矩不够
     -> 加大 vlo(3.5~4.5V)、fres 提到 8~10Hz、母线限流放到 5A
```

脚本按"电压有没有给出去 / 电流有没有上来 / 电流上来了还不转"三种情况分别给建议,
不用自己猜:

脚本输出示例(开环):

```
|E| 有效(|E|>=0.30V)样本: 4830 / 6000 (80%)
反推磁链 |E|/|ωe| = 1.000 mWb (代码里 FOC_FLUX = 1.000 mWb)
末段平均: |E| = 1.10 V, rpm_obs = 1500 rpm
判定: 电机确实转起来了(有反电动势、观测器给出了转速) —— 开环运行成立。
```

## 6. 排查表

| 现象 | 可能原因 | 处理 |
|------|---------|------|
| `vf` 后不转, 2s 后 STALL | **起动转矩不够**(最常见) | `vlo 4.0`、`fres 9`、`ramp 200`;母线限流放到 5A |
| 起步"嗡"一声就不动 | 齿槽+减速箱静摩擦太大 | `vlo 4.5`、`fstart 3`、`ramp 150` |
| 有电压(2.8V)但电流 < 1A | 驱动没输出/EN 没使能/相线没接好 | 先量三相有没有 PWM;`stat` 看 CR1/CCER 自检行 |
| 电流很大(>10A)还是不转 | 要么转矩不够,要么机械卡住 | 加大 `vlo`;断电用手盘输出轴是否顺畅 |
| 转起来但 `vcmd` 一直是 2.8V | 一直没牵入(bit1 恒 1) | 说明 `|E|` 没建立,按上一行处理;牵入后应自动退回曲线 |
| 转起来后电流偏大发热 | `vlo` 太大或 `slope` 太大 | 牵入后退回曲线是自动的;确认 `flags` bit1 已清零 |
| `rpm_obs` 符号与指令相反 | 观测角镜像 | [FOC/src/SMO.c](FOC/src/SMO.c) 第 6 步把 `atan2f(-e_lpf[0], e_lpf[1])` 改成 `atan2f(e_lpf[0], e_lpf[1])`, 重编 |
| 转速上不去、`vdc` 打满 | 电压顶到上限 | 降 `slope`、提母线到 24V |
| 打点丢帧 `drop` 变大 | 主循环/USB 跟不上(现在多了 3 列) | 降低打点频率(`SMO_STREAM_HZ` 改 500) |
| 串口没输出 | USB 未枚举/被占用 | 关掉串口助手,换 COM 号 |

**边界层 δ 的稳定条件**(别随手改小):
`δ > G·k/(1+F) = 0.2514×50/1.9512 = 6.44A`。默认 δ=8A 是 1.24 倍余量,调到 6.44A 以下会发散。

## 8. 连不上调试器的时候(OpenOCD / Cortex-Debug)

Cortex-Debug 里那句 `Failed to launch GDB: Remote communication error ... localhost:50000`
**不是 GDB 的问题** —— 是 OpenOCD 连不上芯片、直接退出了, 于是 50000 端口根本没监听。
用这个脚本直接看原始报错:

```powershell
pwsh -File tools/swd_test.ps1              # DAPLink/MCU-Link, 1MHz
pwsh -File tools/swd_test.ps1 -Speed 100   # 降到 100kHz
pwsh -File tools/swd_test.ps1 -Interface jlink
```

判读:

| 输出 | 含义 |
|------|------|
| `Info : SWD DPIDR 0x2ba01477` + `Cortex-M4 r0p1 processor detected` | 链路通了, 问题在 IDE 配置侧 |
| `Error: Error connecting DP: cannot read IDR` | 探针 OK、**芯片不应答**: 供电/共地/接线/读保护 |
| `No J-Link device found` / 找不到探针 | 探针没插或驱动没装 |

排查顺序(从最常见开始):

1. **目标板到底有没有在跑?** 最省事的判据: 插上板子自己的 USB, 看设备管理器有没有
   `USB 串行设备 (COMxx)`(本工程固件是 USB CDC)。**枚举出来 = 芯片在跑;
   没有 = 板子没供电/没启动**, 那 SWD 当然也读不到 IDR。
   ```powershell
   Get-PnpDevice -PresentOnly -Class Ports | Select-Object FriendlyName, InstanceId
   ```
2. **目标板供电了吗** —— DAPLink/MCU-Link 的 3V3 一般带不动整块 FOC 板, 用板子自己的电源;
3. **共地** —— 探针 GND 必须和板子 GND 接一起(只插 USB 不接 GND 极常见),
   同时把探针的 **VTref/3V3 参考电平**接到板子 3V3;
4. **SWDIO(PA13)/SWCLK(PA14)有没有接反、虚接**, 顺手接上 NRST;
5. **读保护(RDP)** —— 用 STM32CubeProgrammer 连一下看能不能解除;
6. **交叉验证** —— 换个探针/换根杜邦线: 换了好 = 线或探针, 还不行 = 板子/芯片。

### 报错含义对照(实测记录)

| OpenOCD 输出 | 含义 | 结论 |
|---|---|---|
| `CMSIS-DAP: FW Version = 2.0.0` + `Interface ready` | 探针 ↔ PC 正常 | 探针本身没问题 |
| `Error connecting DP: cannot read IDR` | 探针 OK, **芯片不应答 SWD** | 供电/共地/接线/芯片 |
| `No J-Link device found` | 探针没插或驱动没装 | 换 `-Interface` 或装驱动 |
| GDB `... localhost:50000 No such file or directory` | OpenOCD 已退出, 端口没监听 | 是上面某个错误的**后果** |
| GDB `Remote connection closed` | GDB 连上后 OpenOCD 退了 | 同上, 看 gdb-server 终端 |

> 实测: 1000 / 500 / 100 kHz 三档速度都报同样的 `cannot read IDR`,
> 所以**不必再在速度上折腾**, 问题不在信号质量。
>
> 另外: 本工程固件**没有**任何复用/关闭 SWD 引脚的代码(PA13/PA14 一直是调试口),
> 所以"跑起固件后连不上"不是固件把调试口关了。

### 如果 objdump / nm 报 ENOENT

那是 `cortex-debug.armToolchainPath` **写错成可执行文件**了(正确值是工具链的 `bin` 目录):

```
错: "C:/ST/STM32CubeCLT_1.19.0/GNU-tools-for-STM32/bin/arm-none-eabi-gcc.exe"
对: "C:/ST/STM32CubeCLT_1.19.0/GNU-tools-for-STM32/bin"
```

改 VS Code 设置里的这一条即可(它只影响符号分类/反汇编显示, 不影响能不能连上芯片)。

## 附录 B. 中断预算 & 为什么改回 20kHz

**实测:`cyc = 31.67us`,而 40kHz 的预算只有 25us** —— 中断处理不完下一拍就来了,
ADC 采样丢拍、角度积分和真实时间对不上,表现就是**电机不转**。
所以 2026-10 把控制频率从 40kHz **改回 20kHz**(这工程本来就是 20kHz,为 HFI 才提到 40kHz,HFI 已删):

| | 40kHz | 20kHz |
|---|---|---|
| PWM_PERIOD / TIM1 ARR | 2100 | **4200** |

### ★改控制频率时必须一起改的 5 处(漏一处就出怪问题)

| # | 文件 | 改什么 | 漏了会怎样 |
|---|------|--------|-----------|
| 1 | `BSP/inc/App_Config.h` | `APP_CTRL_HZ` | 时间基全错 |
| 2 | `FOC/inc/SVPWM.h` | `PWM_PERIOD = 4200` | 占空比算错,电压不对 |
| 3 | `Core/Src/tim.c` | `htim1.Init.Period = 4200` | 实际频率和代码不一致 |
| 4 | `BSP/src/BSP_Timer.c` | `CCR4 = PWM_PERIOD − 50` | ADC 采样点错位 |
| 5 | `FOC/inc/SMO.h` | **`SMO_BOUNDARY`** | ★观测器**发散**(见下) |

### ★★ 最坑的一条:边界层 δ 必须随控制周期等比放大

前向欧拉离散下 `G=(1−F)/R` 会随 Ts 增大,决定稳定性的是无量纲量 `G·k/δ`:

| 频率 | Ts | F | G | δ | G·k/δ | 闭环极点 | |
|------|-----|------|------|-----|-------|---------|---|
| 40kHz | 25us | 0.9512 | 0.2514 | 8A | 1.571 | −0.620 | ✅ |
| 20kHz | 50us | 0.9048 | 0.4905 | 8A | 3.066 | **−2.161** | ❌ 发散 |
| 20kHz | 50us | 0.9048 | 0.4905 | **16A** | 1.533 | −0.628 | ✅ |

**规则:δ 与 Ts 成正比** —— 40kHz 用 8A,20kHz 用 16A,极点基本不变(只是线性增益 k/δ 减半)。
稳定下限 `δ > G·k/(1+F)`:40kHz 是 6.4A,20kHz 是 **12.9A**。

`python tools/verify_smo.py` 现在**自带这个稳定性自检**,δ 没跟着改会直接报错退出,
不会再让你把一个发散的观测器烧进板子。
