# HFI 高频注入诊断观测器(凸极法)

**一句话**: 在电压上叠一个 1kHz 方波、从电流响应里解出转子凸极轴的角度 ——
**静止就能出角**, 补上 SMO 在 478 电机 rpm 以下没有可信角的空档, 而且它是
编码器 / SMO 之外的**第三条独立测量路径**。

> ★**只观测, 不驱动**: 注入只是一个"探针", PLL 自己估角, 不参与 Park/DePark,
> 不改电流环给定。驱动角永远来自编码器 —— 和 SMO 同一个原则。

代码: `FOC/inc/HFI_INJ.h`(参数+类型+接口)、`FOC/src/HFI_INJ.c`(算法),
接入点: `BSP/src/App_FOC.c`(注入/解调/命令/打点)。
离线自检: `python tools/verify_hfi.py`(**上电前必跑**, 不过就别烧)。

---

## 1. 为什么需要它

| 手段 | 靠什么 | 有效区间 | 用途 |
|---|---|---|---|
| 编码器(+2000点查表) | 磁编码器 | 全速 | **唯一驱动角来源** |
| SMO | 反电动势 \|E\| ≥ 0.3V | ≳478 电机 rpm | 观测诊断 |
| **HFI** | 凸极 Ld≠Lq | **静止 ~ 低速** | 观测诊断 |

SMO 在 478 rpm 以下没有可信角, 而"编码器对齐/查表对不对"这件事恰恰在**静止**时
最想独立验证一次: HFI 的注入沿自己估计的轴走, 完全不看编码器, 所以它给出的角度
和编码器对上了, 说明两边都对; 对不上, 就是有账要查。

---

## 2. 接线与时序(为什么这么接)

```
每拍 10kHz:
  ADC1 分支(电流环):  Clark → PI → DePark → [SMO 快照] → [+ HFI 注入] → SVPWM/CCR
  ADC2 分支:          编码器角更新 → SMO → HFI_Tick(带通 → 解调 → PLL@2kHz)
```

* **注入方向 = PLL 自己估计的 d 轴 θ̂**(`HFI_INJ()` 输出 `±U·(cosθ̂, sinθ̂)`)。
  ★这是要害: 若改成沿**编码器**轴注入, 电流矢量就跟着编码器轴走, 解调量变成
  ∝sin(Δθ) 的各向同性项, **凸极根本没参与** —— 观测器只是在跟踪自己注入的轴,
  什么也验证不了。判据见 `verify_hfi.py` 的 [1b] 节: 解调幅度必须与凸极率成正比
  (仿真里 20% vs 2% = 10.11 倍)。
* **采样在前、写电压在后**: 本工程 ADC 注入组在 CCR4 时刻采完, 中断里之后才写
  CCR ⇒ 本拍采到的电流反映的是**上一拍**写下去的电压, 所以解调要用 `sign_prev`
  加权。反过来(先写电压再采样)每次采样跨两段电压, 解调里会混进一个与角度无关的
  偏置 —— 归档版 `build/backup_closedloop/HFI.h` 专门警告过这件事, 仿真里也复现了。
* **解调用未滤波的 αβ**(`ialpha/ibeta`, 不是 `ia_filt/ib_filt`): 注入是 1kHz 方波,
  任何低通/中值滤波都会把它修掉。
* 注入放在 SMO 快照**之后**: SMO 的电流输入是低通后的, 电压若带 1kHz 注入, 两边
  口径不一致会给观测器灌进假反电动势。

## 3. 命令(USB CDC, 与 `cal/ang/vofa` 同一套)

| 命令 | 作用 | 默认 |
|---|---|---|
| `hfi [0\|1]` | 注入开关(不带参数 = 取反) | **0(关)** |
| `hfiu <V>` | 注入幅值 0.05~1.20V | 0.30V |
| `hfik <A>` | 手动指定解调增益 Kth(一般不用, 固件会自标定)。**也是"环路增益旋钮"**: 调大 = 环路变慢 | 自动 |
| `hfikd <A·s/rad>` | **环路阻尼系数**(误差里减掉 kd·ω), 抵消"与注入轴转速同向的假误差"(见 §8.5 负阻尼) | 1.5e-3 |
| `hfin [0\|1]` | 2·ωe 陷波开关(★见第 7 节, 默认关) | **0(关)** |
| `ang 100` | 文本打点, 末尾带 `hfi=… herr=… hsnr=…` | |
| `vofa 500` | 打点流, 现在 **12 通道**: `corr,raw,lut,mech,spd,out,iq,vdc,obs,err,hfi_theta,hfi_err` | |

`# hfi` 诊断行(20Hz, 只在使能/报过故障时打):

```
# hfi en=1 flt=0 nt=0 U=0.30/0.30V id=+0.267 iq=+0.010 kth=0.0316(meas 0.0316) \
      snr=73.1 sal=18.1% err=+0.2deg w=+0.0rad/s rpm=+0 nosh=0.0Hz us=1.85 clamps=0
```

| 字段 | 含义 | 怎么看 |
|---|---|---|
| `en` | 注入开关 | `hfi 1` 打开 |
| `flt` | 故障码: 0=正常 **1=高频过流** **2=失锁/跑飞**(ω 钉在限幅 >75ms) **3=超出适用转速** **4=标定不可信**(已自动转入 hfiscan) **5=已扫描仍不可信(NO-GO)** **6=扫描期间轴按不住** | ★**2 和 4 都会自动转入静态扫描**(见 §8.5); 其余自动撤注入; 重新 `hfi 1` 可清 |
| `ncal`/`nsc`/`step` | 标定窗启动过几次 / 扫描启动过几次 / 当前扫描第几档 | ★一眼看出是不是在反复重来(现场出现过 `cal=1` 持续 2s + err 以 15° 步进: 那其实就是**自动扫描的第 0…N 档**) |
| (开机第一行) | `# hfi build: <日期> <时间>` | 每次上电打一次 = **构建指纹**; 和 `build/Debug/F405_M3508_FOC.elf` 的时间戳对一下就知道烧的是不是当前这一版 |
| `nt` | 陷波开关 | 默认 0(见第 7 节) |
| `cal` | **1 = 正在标定窗**(32ms, θ̂ 被钉在编码器 ±45° 上, 此时角度无意义) | 使能后头 32ms 是 1 |
| `U` | 实际/设定注入幅值 V | 受 vdc 线性区限制时会低于设定值 |
| `id` | 解调出的**载波电平** A | ≈0.25~0.28A @U=0.30V(实测与仿真一致) |
| `iq` | 解调出的误差信号 A | 锁上后应接近 0 附近摆动 |
| `kth` / `meas` | 解调增益 A(标定窗两点法实测) | 与凸极率成正比: 2%≈0.024A, 20%≈0.033A |
| `bias` | 标定窗量到的**解调偏置** A | **环路里会减掉它**; 它大 = 死区/PWM 不对称/传感器失配大 |
| `snr` | Kth / 拟合残差 = **凸极信噪比** | **★判据: <3 就是这点凸极不够用, 别信它的角** |
| `sal` | 反推的凸极率 %(只当数量级) | 各凸极率下常数散 0.62~1.19, 别当真值 |
| `err` | HFI 角 − 编码器角(折到 ±90°) | 静止时应稳定在几度内 |
| `w` /`wenc` | PLL 估的角速度 / **编码器角速度** | 锁上时两者应接近; 差很多 = 没锁 |
| `us` | HFI 每拍耗时峰值(DWT 实测) | 预算 50us/拍(10kHz) |
| `clamps` | 被 vdc 线性区限幅的拍数 | 长期增长 = 该降 `hfiu` |

## 4. 参数是怎么来的(10kHz 重推, 全部在 `HFI_INJ.h`)

| 量 | 值 | 推导 |
|---|---|---|
| 半周期 / 方波 / 解调率 | 5拍 / 1kHz / 2kHz | 极性每 5 拍翻一次; 解调率 = fs/5 |
| 注入幅值 | 0.30V | `I_hf ≈ (U/R)·F(τ)`, `F = 1−(τ/T)(1−e^(−T/τ)) = 0.368 @T=τ`, τ=L/R=0.5ms ⇒ ≈0.57A |
| 带通 | f0=1kHz,Q=3,两级级联 | RBJ 常峰值增益: `α=sin(w0)/(2Q)`, `b0=α/a0,b1=0,b2=−α/a0,a1=−2cos(w0)/a0,a2=(1−α)/a0`; 中心处 \|H\|=1、相位=0 ⇒ 解调不偏相。两级是为了压住 58~116Hz 的基波(单级只 −15dB) |
| PLL | Kp=250, Ki=25000 | 归一化成 sin(2Δθ) 后进 PI: `ωn=√(2Ki)=224rad/s(35.6Hz)`, `ζ=Kp/ωn=1.12`(照 `mf_HFI_Observer.m`) |
| 环路 Ts | 0.5ms | ★只在有新解调值时跑一步。原代码每拍都进 PI 而 err 每 5 拍才更新 ⇒ 等效增益 ×5 |
| Kth | 实测自标定 | RLS 拟合 `err_raw = Kth·sin(2Δθ)`; 默认 0.05A 只在没标定完时兜底 |
| `HFI_SAL_K` | **0.80** | 由离线仿真按当前两点法标定(单点散 0.62~1.19, 只能当数量级) |
| 标定窗 | 64 次解调 = **32ms** | 使能后 θ̂ 钉在编码器 **±45° 两个点**上, 每点 16 次、丢前 8 次, 2 轮 |
| 适用转速 | \|ω_enc\| ≤ **62.8 rad/s**(≈10Hz 电 ≈86 电机 rpm) | 超限自动 flt=3(见第 5/7 节的实测表) |

### 相对参考实现(`HFI_INJ.c`)的 10 处改动

| # | 改动 | 为什么 |
|---|---|---|
| D1 | `controller->V_d += Voltage_inj*1024` (Q10) → `HFI_INJ(&vα,&vβ)` 浮点伏特矢量 | 本工程没有 `ControllerStruct`, 且**注入方向必须是 θ̂** |
| D2 | 补上前端: αβ 各两级级联带通 | 参考代码里 BPF 只 init 没被调用 |
| D3 | 环路(陷波/PI/积分)只在新解调值上跑一步(2kHz) | 原代码等效增益 ×5 |
| D4 | 删掉 `Idq_LPF`/`Idq_to_Idqf` | 全文件无调用点(死代码), 本工程有 `LPF.h` |
| D5 | `PLL_LPF` 的 static 状态改到结构体字段 | 函数内 static 多实例会串 |
| D6 | 新增诊断/保护: Kth、偏置、SNR、凸极率、DWT 计时、过流/失锁/超速保护 | 观测模式才有的条件, 也是"够不够用"的判据 |
| D7 | **两段式标定**: 使能后 32ms 标定窗(环路不闭, θ̂ 钉在 ±45° 两点) → Kth 冻结 | ★直接闭环让环路"自己标定"会拿瞬态样本算 Kth(实测把 w 顶到限幅) |
| D8 | **交接**: θ̂ 对到编码器(零误差) + 积分器预置成编码器速度(前馈) | 避免初始误差 → 积分器 wind-up → 环路跑飞。角度仍是 HFI 自己解的 |
| D9 | **环路里减掉标定窗量到的解调偏置** | ★II 型环会把 DC 偏置当"频差"用积分器抵消 ⇒ **丢掉转速跟踪**(现场跑飞根因) |
| D10 | **转速门限**: 超 62.8rad/s 自动 flt=3 + 撤注入 | 偏差随转速线性长(实测表), 超范围就明确拒绝, 不给垃圾角度 |

## 5. 上电步骤与判据

```powershell
# 0) 先跑离线自检(不上电, 秒级) —— 不过就别烧
python tools/verify_hfi.py

# 1) 烧写后: 电机固定牢、轴上不加载; ★**让电机停住**(HFI 只在这里有意义 ——
#    要测的正是"编码器在静止/极低速下对不对", 转起来该用 SMO)
# 2) 打开注入
hfi 1
#    头 32ms 是标定窗(cal=1): θ̂ 被钉在编码器 ±45° 两个点上量 Kth 和偏置,
#    这段时间的角度无意义。之后自动零误差交接并开始正常观测。
#    等 1~2s, 看 # hfi 行:
#      en=1 flt=0 cal=0 U=0.30V id≈0.25A  →  载波起来了
#      kth/bias/snr                       →  ★凸极够不够 + 解调偏置大不大
#      err / w 与 wenc                    →  锁上后 err 应稳定几度内、w≈wenc
#    若 flt=3: 转速超范围了, 把电机停住再 hfi 1
# 3) 想看波形: vofa 500, 把 hfi_err(第12通道)和 err(第10通道)叠一起看
# 4) 不要了就关掉(注入是实打实在加电压)
hfi 0
```

**判据(按重要性排序)**

1. `snr ≥ 3` —— 这是硬门槛。`snr < 3` 说明这点凸极的信噪比不够, 角度会随偏置乱跑;
   这时候**别信 HFI 的角**, 它只能告诉你"这颗电机的凸极太小, 这条路走不通"。
2. `flt = 0` 且 `cal` 已经是 0。`flt=3` = 转速超出适用范围(见第 7 节), `flt=2` = 失锁。
3. `err` 稳定(静止时几度内、不随转速漂) —— 说明 HFI 和编码器两条独立路径一致。
4. `us`(每拍耗时)必须 < 50us。超了先解决中断预算, 别调参数。
5. `w` 与 `wenc` 应接近; 差很多就是没锁(别只看 `err`, `err` 折到 ±90° 后会骗人)。

**★必须在静止/极低速下用**(实测, 20% 凸极, 1LSB 噪声, 见 `verify_hfi.py` 的 [0b] 节):

| 电频率 | 电机 rpm | 末段误差 | RMS | 说明 |
|---|---|---|---|---|
| 0Hz | 0 | **−0.03°** | **0.26°** | 主战场(补 SMO 的 478rpm 空档) |
| 2Hz | 17 | −0.9° | 0.32° | 可用 |
| 5Hz | 43 | −2.3° | 0.43° | 可用 |
| 10Hz | 86 | −4.4° | 0.61° | 门限处(固件拒绝), 余量其实还有 |
| 24Hz | 206 | −10.3° | 1.3° | 超门限 |

偏差随转速线性长 = 解调的正交泄漏(注入轴在转, 半周期平均不再是纯载波),
标定窗只能测掉其中的偏置部分。所以 `HFI_MAX_W` 定在 10Hz(≈86 电机 rpm) ——
**超过就明确拒绝, 不给一堆看着像角度的垃圾**。转起来以后该用 SMO/编码器。

**仿真给出的定量预期**(静止, 1LSB≈9.8mA 噪声, U=0.30V):

| 凸极率 | Kth[A] | 锁定误差 RMS | snr |
|---|---|---|---|
| 2% | 0.024 | 0.6°(均值偏 −25°) | 1.5 ✗ |
| 5% | 0.031 | 0.4° | 4.4 ✓ |
| 10% | 0.038 | 0.4~0.6° | 11~49 ✓ |
| 20% | 0.033~0.052 | 0.3~0.5° | 32~74 ✓ |

⚠ 表贴磁钢的 M3508 凸极率通常只有几个百分点。**这颗电机实测是多少, 上电后看
`sal`/`kth`/`snr` 就是答案** —— 如果 `snr` 只有 1~2, 这条路基本走不通(不是代码问题)。

## 6. 离线自检做了什么(`tools/verify_hfi.py`)

| 节 | 内容 | 本次结论 |
|---|---|---|
| [0] | **复现现场**: 转子 24Hz + 1LSB 噪声, 对比改前/改后 | 改前: err +56°/RMS 52°、kth 乱、角度全垃圾; 改后: **干净地拒绝(flt=3)** |
| [0b] | **转速适用范围**: 0/2/5/10/24Hz 逐档 | 0Hz RMS 0.26° → 5Hz 0.42° → 10Hz 0.62°; 偏差随转速线性长 ⇒ 门限 10Hz |
| [1] | 滤波器系数: 从公式重算并与 `HFI_INJ.h` 字面值逐一比对; 再算 \|H\|/相位 | 中心 \|H\|=1.000000、相位 0.000°; 58Hz 基波被级联带通压到 0.0004 |
| [1b] | **判决性实验**: θ̂ 钉在不同 Δ 上直接量 err(Δ) | 严格 ∝sin(2Δ), 20%:2% 幅度比 **10.11** ⇒ 真凸极观测器 |
| [2] | 环路极性: θ̂ 初值偏 ±30° 必须收敛 | 两个方向都收敛到 0.00° ✓ |
| [2c] | 环路增益 × 陷波扫描 | ★陷波一开就振(与增益无关), 关掉后任何增益都稳 ⇒ 默认关 |
| [3] | 锁定能力: 凸极率 × ADC 噪声 | 10% → +0.5°(RMS 0.62°), 20% → +0.2°(RMS 0.45°); 2% 时 snr=1.5 ✗ |
| [4] | 基波串扰: 叠加 1A@58Hz | 仍锁到 1.0~1.3° ✓(级联带通的功劳) |
| [5] | 标定常数核对 | 仿真反推 `HFI_SAL_K ≈ 0.77` = 头文件值(比值 0.96) |

自检**发现并修掉的真问题**(每一个都是先烧板才会踩的):
1. BPF 系数抄错一位(`a1` 第 6 位) —— 数值比对直接报出来。
2. 注入沿编码器轴 ⇒ 凸极不参与(整个观测器是假的) ⇒ 改成沿 θ̂ 注入(判决实验 10:1)。
3. 陷波默认落在 PLL 带宽内 ⇒ 环路自振 ⇒ 默认关。
4. **两段式标定漏实现**: 文档写了标定窗, 固件却直接闭环 ⇒ 现场 w 钉在 ±450rad/s、
   kth 掉到下限(2026-10 实测)。
5. 两点法**符号写反**(+45° 点是 b−Kth 不是 b+Kth) ⇒ Kth 拟成负数撞下限。
6. 标定窗**换点后没等稳**: 每点只丢 3 次(1.5ms) ⇒ Kth 偏大 1.66 倍、还冒出 −0.05A 假偏置;
   加长到每点 16 次、丢前 8 次(4ms)后, 两点量出来是干净的 ±0.0332、偏置 0.0000。
7. **环路没减偏置**: II 型环会把 DC 偏置当频差、用积分器抵消 ⇒ 丢转速跟踪 ⇒ 跑飞。
8. 没有转速门限 ⇒ 205rpm 那种明显超范围的工况也给一堆"看着像角度"的数字 ⇒ flt=3。

## 7. 已知限制(不要当成 bug)

* **模 π 歧义**: 凸极法只能定到磁轴(sin2Δθ 在 Δ=0 与 Δ=π 同为零), 所以打点里
  `hfi_theta` 与 `corr` 差 180° 是正常的; `hfi_err` 才是判据(已折到 ±90°)。
  要定极性得另外用一次编码器(归档版 HFI 的 `HFI_StartCloseLoop` 就是干这个的)。
* **陷波默认关**: 静止时 2·fe≈0, 陷波被压到 5Hz, 正好落在 35Hz 环路带宽内, 相位
  余量被吃光 ⇒ 自振(仿真: 开 → RMS 19°, 关 → 0.3°)。只有转起来(2fe 远高于环路
  带宽)才有意义, 那时该用 SMO。要试验就 `hfin 1`。
* **凸极率门槛**: 见第 5 节判据。这是物理限制, 调参数救不了。
* **L/R 时间常数**: τ=L/R=0.5ms 与半周期 T=0.5ms 同量级, 已经不是纯感性区 ——
  半周期平均解调靠的是 R 限制下的平均值(不是 di/dt), 灵敏度约为纯感性区的 53%。
  这些都固化在 `HFI_SAL_K` 和仿真里了。
* **转速相关偏差(最大的限制)**: 转子一转, 注入轴就在转 ⇒ 半周期平均不再是纯载波解调,
  多出一个 ∝ω 的正交泄漏(实测: 5Hz −7°, 10Hz −12°, 24Hz −25°, 而 RMS 只有 0.3~1.3°)。
  标定窗只能测掉其中的**常数偏置**部分, ∝ω 那部分没补。所以:
  **`HFI_MAX_W`=62.8rad/s(≈86 电机 rpm) 以上直接 flt=3 拒绝**, 别在转起来以后用它
  —— 那个区间编码器和 SMO 都好好的, 本来也不需要 HFI。
* **建议只在静止用**: 想用它在低速跑, 先把 `HFI_MAX_W` 放开, 并接受上表那几度的系统偏差
  (要做补偿得再标一个 ∝ω 系数, 目前没做)。
* **没做闭环**: 目前只用它的角做对照。要做无感低速闭环(用 HFI 角跑电流环)还需要:
  角度连续化 + 极性辨识 + 在 CC4 时刻写 CCR 的电压切换时序, 而且**先得确认凸极率够**。
* **建议只在静止/低速用**: 转起来以后 SMO 更合适。另外 PLL 若在高转速下失锁, 注入
  矢量的方向会跟着漂(它跟着 θ̂ 走) —— 后果只是注入不再沿 d 轴、有点额外的高频电流和
  1kHz 声音, **不影响驱动**(驱动角永远是编码器), 关掉 `hfi 0` 即可。
* 注入时会有明显的 **1kHz 声音**, 以及约 `I²R = 0.25²×0.194 ≈ 12mW` 的铜损, 都正常。

## 8.5 ★现场失效记录: 硬件不对称盖过凸极信号(2026-10, 电机静止实测)

这一条是这套 HFI 目前**最主要的拦路虎**, 比"凸极率小"更致命, 单独记一节。

**现象**(U=0.30V, 电机静止, 驱动用速度环"抱住"轴, 保持电流 ≈0.2A):

```
# hfi en=1 flt=0 cal=0 U=0.30/0.30V kth=0.1338(meas 0.1338) bias=+0.1503 snr=0.6 sal=24.8% err=-18.0deg w=+443.5/+0rad/s
```
- 标定窗量到 `kth=0.1338`、`bias=+0.1503` —— 而仿真在 20% 凸极下只有 `kth≈0.033`、`bias≈0`;
- 交接后 ω **立刻**钉在 `+443…+450rad/s`(= `Kp + I_LIMIT`), 而编码器是 `+0rad/s`(静止);
- `snr=0.6` → 判据(≥3)判定 **NO-GO**。

**机理(2026-10 现场两次会话定下来的)**:
标定窗把 θ̂ 钉在**编码器 ±45°** 两个点上量增益 —— 而 ±45° 恰好是 `sin(2Δ)` 的**最大灵敏度点**。
现场量到的结果是: **两点几乎相同**(`kth` 撞下限 0.0030)、`bias=+0.1412`(两次会话都稳定在 +0.14)、
而环路却强烈往一边跑。这两条只有在"**响应被转到了 `cos(2Δ)` 上**"时才能同时成立:
- `sin2Δ` 分量≈0 ⇒ 两点相同、标定窗量不到增益(它天生看不见 `cos2Δ`);
- 但 Δ 相关信号其实很大(在 `cos2Δ` 里) ⇒ 环路在 Δ=0 处遇到的是**极值而不是零点**(斜率≈0),
  被一顶就跑 ⇒ ω 钉在限幅。

写成一般形式: 解调量 `err(Δ) = b + K·sin2Δ + C·cos2Δ = b + |E|·sin(2Δ+φ)`, `φ=atan2(C,K)`。
`φ≈±90°` 就是"注入轴与解调轴的参考差了 90°"(约定/接线/采样相位), **凸极信号在 C 里, 没丢**。

**★修法: 转轴, 不要减 C。** 推导: 解调轴转 ρ 后量到的是 `|E|·sin(2Δ−ρ)` ⇒ **ρ = −φ = −atan2(C,K)**。
- `hfiscan`(免锁相 12 点扫描)**自动**算出 ρ 并用 `HFI_SetDemodRot` 转正, 转完 `C→0、K→|E|`;
- 同时把环路增益改用免锁相量到的 `|E|`(而不是那个撞下限的标定值), 然后**自动重开标定窗并接管**;
- ⚠ 早先那版用"减掉 C"的补偿: 只在 **K 本身够大、C 是额外硬件不对称**时才对; 像现场这样
  `K≈0` 时, 减 C 会把**凸极信号一起减掉** ⇒ 必须转轴。

**仿真验证**(`verify_hfi.py` [8] 节, 建模"注入轴不动、解调轴偏 `rot_hw`"):

| rot_hw | 扫描 K | 扫描 C | \|E\| | 推出 ρ_c | 补偿后标定 kth | 环路 |
|---|---|---|---|---|---|---|
| 0° | +0.0308 | −0.0002 | 0.0308 | +0.4° | 0.0332 | 锁定 ✓ |
| **90°(现场签名)** | **+0.0003** | +0.0310 | 0.0310 | −89.4° | 0.0332 | **锁定 ✓** |
| 137° | −0.0223 | +0.0213 | 0.0309 | −136.3° | 0.0332 | 锁定 ✓ |

即: 90° 相位错能**完整复现现场签名**(K 被转空、kth 撞下限), 而转轴后标定与环路**完全恢复**。

**已做成自动链**: `hfi 1` → 标定窗判"不可信"(flt=4) → **自动**跑 `hfiscan`(2.4s, 环路不闭, 不会跑飞)
→ 转轴 + 用 `|E|` 定增益 → 自动重标定 → 接管观测。全程只要 `hfi 1`, 中间保持静止即可。
若扫描显示 `|K|`、`|C|` 都与残差同量级 ⇒ `flt=5`, 那才是真正的 NO-GO(这台电机没凸极)。

**怎么读"自动扫描正在进行"**: 报告里的 `err` 会以 **15° 步进** 从 0 走到 165°(每档 200ms),
同时 `nsc=1`、`step` 递增 ⇒ 这是**正常**的扫描过程, 不是跑飞(`w` 会一直是 0, 因为环路没闭)。
扫描期间**不套** 86rpm 那个转速门限: 每档自己判"轴动没动", 单档超 `HFI_SCAN_W_MAX`(5rad/s≈7电机rpm)
就**只作废这一档重来**(最多 4 次), 免得手碰一下就把 2.4s 白跑; 实在按不住才 `flt=6`。
表格里每档带 `wmax`, 越小越可信(注入本身会让转子缓慢爬行, 约 1rad/s 属正常)。

**对策余下部分(按性价比)**:
1. **加大注入** `hfiu 0.8`~`1.0`(≤1.2V): `|E| ∝U`, 转轴后 snr 直接改善; 改完要重跑 `hfiscan`。
2. **去掉保持电流**: 用速度环"抱"住轴会灌 ~0.2A 直流, 它和 HF 纹波一起决定死区符号,
   是 `b`(常数偏置 +0.14A)的主要来源。改 `cur 0 0` 或机械夹住再复测。
3. **死区补偿**(SVPWM 按相电流符号修正): 根上的修法, 对整个驱动的低速波形也有好处。
4. 若转轴后 `|E|` 仍与残差同量级: 才是"这台电机凸极不够"的真 NO-GO。

## 9. 长尾坑

* **两点法的符号**: `err = +Kth·sin(2(θenc−θ̂))` ⇒ θ̂=θenc**+45°** 那一点是 `b−Kth`,
  −45° 那一点是 `b+Kth`, 所以 `Kth = (err₋ − err₊)/2`。写反了 Kth 会拟成负数、撞下限,
  而环路照样"看起来在锁" —— 仿真里就是这么抓出来的。
* **标定窗一定要等稳**: 换点后电流/带通的建立时间是**毫秒级**(τ=L/R=0.5ms+带通群延迟),
  每点只丢 1~2ms 会把 Kth 抬高 1.5 倍以上、还凭空造出一个大偏置。现在每点 16 次解调、
  丢前 8 次(4ms)。
* 改 `APP_CTRL_HZ` 要连带改 `HFI_TS/HFI_TS_LOOP/HFI_HALF_TICKS`(解调率跟着走),
  并且重跑 `verify_hfi.py` 重标 `HFI_SAL_K`。
* `HFI_HALF_TICKS` 一改, 带通中心频率就变了(它必须等于方波基频), 系数要重算 ——
  `verify_hfi.py` 的 [1] 节会直接报不一致。
* `vofa` 提到 12 通道后 500Hz 约 54kB/s, 已接近 USB CDC 的 ~60kB/s: 丢帧就看
  `vofa 0` 打印的计数, 或降到 300。
* 新增源文件要能被 `tools/build.ps1` 编到: 它从 `build/Debug/build.ninja` 解析
  "目标文件→源文件"表, 所以 `FOC/src/HFI_INJ.c` 在 ninja 里补了一条边(带注释)。
  将来重跑 cmake 会自动生成同样的边(`CMakeLists.txt` 用的是 `file(GLOB_RECURSE)`),
  但**本机 cmake 启动就卡住**(见 `tools/build.ps1` 顶部说明), 所以当时是手工补的。
* 使能/失锁后**必须处于静止**再 `hfi 1`: 标定窗要求"两点准", 转子在转会把两点污染
  (现场就是这么跑飞的)。命令里已经加了"先问转速"的检查: 超范围会直接拒绝并打印当前
  转速, 不会让你看到"刚开就 flt=3"。
* **`hfi_w_enc`(编码器角速度估计)必须每拍维护**: 它同时用于转速门限和交接前馈。
  早先版本把它放在"注入关着就早退"之后 ⇒ 关闭期间不更新 ⇒ 下次使能第一拍的差分是
  "整段位移"的卷绕值 ⇒ 速度估计炸成上千 rad/s ⇒ 门限立刻误判 flt=3(现场日志
  `w=-1361rad/s`)。现在它在函数最前面、无条件每拍跑, 并且 `|dw|>0.3rad` 判为毛刺丢弃。
* **`HFI_SetEnable()` 里 `hfi_enable` 必须最后置位**: 中断(10kHz)随时会进来跑转速门限;
  若先置位再复位滤波器/启动标定窗, 门限可能在中途把状态清掉, 而 SetEnable 接着又把
  `cal_run` 置 1 —— 留下 `en=0/flt=3/cal=1` 这种再也清不掉的矛盾状态(现场日志)。
