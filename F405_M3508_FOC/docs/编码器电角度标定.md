# 编码器电角度标定(2000 点查表)

固件里已经带好了整套东西, 台架上按下面四步走一遍就行。

## 为什么不能拿闭环标定

速度环的反馈就是这个编码器。用它闭环去标它自己的角度误差, 环路会自动把误差抵消掉
—— 标出来永远是 0。**必须用独立基准**: 固件自己积分出来的电压矢量角度 φ
(低频旋转, 与晶振同源、绝对均匀), 用它拖着转子转, 转子被磁场锁住时 φ 就是真实电角度。

## 步骤

```
# 1. 烧录当前固件, 打开串口(115200, USB 虚拟串口), 应看到:
# ready. 命令: cal | cal stop | lut | enc | stat | help (LUT 2000 点, valid=0)

cal                  # 开始标定。电机会: 对齐0.5s -> 升频2s -> 匀速拖转20s
# 期间每 0.5s 一行进度: # cal 采集中: f=2.00Hz cycles=12.3/40 样本=61500
# 结束:
# cal DONE: OK | N=200186(原始粗角度扫过 78.1 圈) | 覆盖格 2000/2000
#   | 原始均|err|=0.3070rad(17.59deg) max=0.4936rad | ★查表后残差=0.3070rad(17.59deg)
# 表的构成: 直流(对齐偏差)=+17.63deg  峰峰(非线性)=16.92deg → 以对齐偏差为主

cal                  # ★再标一遍: 这一遍同时是"验收" —— 此时表已经生效,
#                      查表后残差应当明显小于原始均|err|(第一遍时表是全 0, 两者必然相等)

lut                  # 导出 2000 行 "idx,rad"
```

读懂那两行:

* `覆盖格` 必须是 **2000/2000**。不满 = 转子没转够/卡住, 表作废(失败原因会直接打出来)。
* `原始粗角度扫过 N 圈` 应当 ≈ `APP_CAL_CYCLES`(40)。接近 0 = 转子压根没被拖动。
* **`★查表后残差` 才是表好坏的判据**: 第二遍它应该从 17.5° 掉到几度。
  没掉 = 误差不是角度的确定性函数(传感器噪声/转子在齿槽里抖), 这种表修不了。

实测(本机这颗 M3508 + 板载编码器), 已固化进 `FOC/src/Encoder_Lut.c`:

```
直流(对齐偏差) = +17.54 deg      <- 表生效后就是这个值在做绝对对齐(不再叠加 ELEC_OFFSET)
峰峰(总非线性) =  16.58 deg
有效值         =   3.56 deg
```

谐波分解(`python tools/analyze_lut.py`, 看清误差到底来自哪儿):

| 每电周期 | 每机械转 | 幅值 | 来源 |
|---|---|---|---|
| 12 | 84 | 3.11° | **齿槽族**(LCM(12槽,14极)=84/转): 转子被齿槽拽住的机械滞后 |
| 2 | 14 | 2.92° | **编码器 sin/cos 幅值/正交误差**(椭圆的二次谐波) |
| 4 | 28 | 1.58° | 同上, 高次 |
| 8 / 10 / 16 | 56/70/112 | 1.0/0.9/0.6° | 同上(传感器非线性) |

**齿槽族只占总能量的 ~40%, 其余是编码器自身的非线性** —— 结论:
* 加电压(`calv`)只能压掉那 40% 的机械滞后, 大头(sin/cos 非线性)只有查表能修;
* 原来固件硬编码 `ENCODER_ELEC_OFFSET=0.5045rad(28.9°)` 做对齐, 实测是 **+17.54°**,
  也就是之前**系统性偏了约 11°**, 再叠加 ±8° 的周期误差 —— 这就是"能转但抖、扭矩上不去"的来源。

导出的两种收法(任选):

```powershell
# A. 让脚本自己从串口收(会替你发 lut 命令)
python tools/lut_capture.py --port COMxx --gen

# B. 串口助手里把 lut 的输出存成文件, 再喂给脚本
python tools/lut_capture.py --in tools\enc_lut.csv --gen
```

`--gen` 会把表写成 `FOC/src/Encoder_Lut.c`(固化), 然后:

```powershell
pwsh -File tools/build.ps1     # 重新编译
```

烧进去之后开机横幅里 `valid=1`, 表就永久生效了, 不用每次上电重标。

## 怎么看结果

```
表统计:
  直流(电角度对齐偏差) = +0.5123 rad (+29.35 deg)  ← 这就是原来的 ENCODER_ELEC_OFFSET
  周期误差 峰峰 = 0.1299 rad (7.44 deg)   有效值 = 0.0381 rad (2.18 deg)
```

* **直流分量** = 机械/磁钢安装带来的对齐偏差。表生效后固件**不再叠加**
  `ENCODER_ELEC_OFFSET`(表里已经含了), 这一点在 `Encoder_GetElecAngle()` 里。
* **峰峰值** = 编码器在一个电周期内的非线性误差, 就是要被表吃掉的那部分。
  峰峰 > 1 rad(57°) 基本可以判定是坏数据(转子打滑), 脚本会警告, 别固化。

## 参数怎么调(`BSP/inc/App_Config.h`)

| 宏 | 默认 | 说明 |
|---|---|---|
| `APP_CAL_FREQ_HZ` | 2.0 | 拖转电频率。**硬约束 ≤5Hz**: 10kHz 采样要分辨 2000 格 |
| `APP_CAL_VOLT` | 0.60 | 拖转电压。电流≈V/Rs(0.194Ω)≈3A。**加大电压=磁场更硬=齿槽引起的转子滞后更小=表更准**, 但发热也更大 |
| `APP_CAL_CYCLES` | 40 | 采集电周期数(2Hz×40=20s), 每格约 100 个样本 |
| `APP_CAL_RAMP_S` | 2.0 | 升频时间, 太短转子会顿一下 |

## 看波形(VOFA+)

```
vofa 500     # FireWater 文本流, 500Hz; vofa 0 关; 不带参数 = 开关
ang 100      # 另一种: 人看的文本打点(带字段名), 二者互斥
```

VOFA+ 里: 协议选 **FireWater**, 端口选板子自己的 USB 串口, 波特率随便(CDC 不看这个)。
通道顺序(12 路):

| # | 通道 | 单位 | 看什么 |
|---|---|---|---|
| 0 | corr | rad | **查表后的电角度** —— 恒速下应匀速直线上升 |
| 1 | raw | rad | 粗角度(未校正); 与 corr 的差就是表在补的量 |
| 2 | lut | rad | 表项本身(≈ +0.15~+0.44) |
| 3 | mech | rad | 电机轴机械角 |
| 4 | spd | rpm | **电机侧**转速 |
| 5 | out | rpm | 输出轴转速 = spd/19 |
| 6 | iq | A | 转矩电流 |
| 7 | vdc | V | 母线电压 |
| 8 | obs | rad | SMO 观测电角度 |
| 9 | err | rad | SMO 角 − 编码器角 |
| 10 | hfi_theta | rad | HFI(PLL)电角度 [0,2π); ★凸极法只有模 π 的轴, 差 π 正常 |
| 11 | hfi_err | rad | HFI 角 − 编码器角(折到 ±π/2) —— **这个才是判据** |

**采样是在 10kHz 中断里按整数分频做的**(不是主循环凑时间), 所以时间轴是准的;
`vofa 0` 关掉时会打印累计丢帧数 —— 非 0 说明串口没跟上(把频率降到 300)。
速率上限 ~500Hz: USB CDC 只有约 60kB/s, 1000Hz 会丢帧;
**12 通道 @500Hz ≈ 54kB/s 已经贴近这个上限**, 丢帧就降到 300。

## 滑模观测器对照(独立验证对齐)

**SMO 只观测、不驱动**——驱动角永远来自编码器。它是另一条完全独立的测量路径
(靠反电动势, 不用编码器), 所以两个角度对上了, 说明编码器的对齐是真的。

★**本工程是 10kHz, SMO 参数必须按 Ts 重标**(存档那版是 20kHz):

| 控制频率 | Ts | F | G | δ | G·k/δ | 闭环极点 | |
|---|---|---|---|---|---|---|---|
| 20kHz | 50us | 0.9048 | 0.4905 | 16A | 1.533 | −0.628 | ✅ 存档版 |
| 10kHz | 100us | 0.8187 | 0.9344 | 16A | 2.920 | **−2.10** | ★**发散** |
| 10kHz | 100us | 0.8187 | 0.9344 | **30A** | 1.557 | −0.739 | ✅ 现在 |

两个低通的 α 同样要按 `α = 1−exp(−2π·fc/fs)` 换算, 否则截止频率跑偏(高速时把 |E| 压掉)。
**改这些数值前先跑 `python tools/verify_smo.py`** —— 不满足稳定性它会直接报错退出, 别绕过。

```
vofa 500      # 12 通道: corr,raw,lut,mech,spd,out,iq,vdc,obs,err,hfi_theta,hfi_err
ang 100       # 文本打点, 末尾带 obs/err/emf/off 以及 hfi/hfi_err/hfi_snr
```

| 看什么 | 期望 |
|---|---|
| `corr`(ch0) 与 `obs`(ch8) 叠一起 | 基本重合 |
| `err`(ch9) = obs − corr | 在 0 附近小幅摆动(几度) |
| `emf` | **必须 > 0.3V(≈478 电机 rpm 以上)**, 否则 `v=0`, 观测角不可信 |
| `off` | 两套角度口径之间的固定常数差(存档版用 `OL_ANGLE_OFF_DEF=+0.4936rad` 抵消)。固件先对齐一次再慢速跟踪 —— **只影响显示, 不碰控制** |

## 标定失败(cal DONE: ★失败: ...)

| 现象 | 原因 | 处理 |
|---|---|---|
| 覆盖不足 + 扫过 ≈0 圈 | 转子没被拖动(齿槽/静摩擦咬住) | 加大 `APP_CAL_VOLT`; 确认轴上没负载 |
| 覆盖不足 + 扫过几十圈 | 转是转了但没扫满一圈 | 同上, 或检查轴系打滑 |
| 平均误差过大(>34°) | 转子打滑, 基准丢了 | 加大电压, 或把频率降到 1Hz |
| 样本不足 | 采集中途被中止/超时 | 看前面的 `code=` 提示 |
| 中途 code=3 | 编码器无效(信号太弱/断线) | 先 `enc` 看 sin/cos 极值和 valid |
| 中途 code=1 | 母线欠压 | 查供电 |
| 中途 code=2 | 超时(90s) | 一般是有一步卡住了 |

★失败时**统计量照样打印**(N/扫过圈数/覆盖格/误差), 不要只看"失败"两个字。
